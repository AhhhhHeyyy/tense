# 閱讀模式選擇器 規格

> 狀態：草稿，待坑主／事件線編輯複核。本文件性質同共筆〈spec/〉——規格文件，不含最終程式碼，落地前應可被檢視、被質疑。

## 0. 這個機制解決什麼問題，不解決什麼問題

**背景**：原始構想是漸進式引導（onboarding）——依「你是誰、目的、偏好」自動判斷、自動調整介面呈現的詳細程度。這個構想在多線合併功能（`spec/candidate_linker.md` 同期的 Phase 1）落地後被邊緣化：自動判斷邏輯與多線同框顯示的邏輯互相干擾，曾發生使用者透過路徑 C（無法重現的操作序列）被誤切換模式一次。自動判斷「你是誰」這件事本身也隱含著替讀者分類、貼標籤的風險，不符合這個專案「不排名、不做聚合效率比較」的一貫立場（見 `spec/candidate_linker.md` 1.1 節同精神）。

**解決的問題**：讓讀者能自己選擇偏好的閱讀模式（資訊密度／措辭方式不同），不必依賴系統猜測。

**不解決的問題**：不做使用者輪廓判斷、不做個人化推薦、不做任何形式的「猜你是誰」邏輯。

## 1. 硬性排除（不可違反，違反視為規格不符）

1. **不分身分、不分目的**。模式選擇只能是讀者主動、明確的操作（例如頁面上的切換按鈕），不能有任何自動偵測「這個人像記者／像關心的公民／像研究者」之類的邏輯，也不能用來源網址、瀏覽器語言等訊號自動預設模式。
2. **兩種模式顯示的內容量絕對相同**。`pro` 與 `plain` 兩種模式只能是**措辭方式不同**（例如專業用語 vs. 白話說明），不能有一種模式看得到的資訊比另一種少或多。任何一種模式都不能被實作成「精簡版」，否則違反企劃案一貫的「不做資訊落差」原則。
3. **不做用戶追蹤，模式偏好只存 localStorage**。不送後端、不寫 cookie、不接第三方分析。且**別人分享給你的連結，不能被你自己儲存的偏好覆蓋**——如果 A 分享一個連結給 B，B 開啟時如果被 B 自己先前存的模式偏好覆蓋掉 A 想呈現的模式，這條連結的「可引用性」（別人點開看到的東西應該跟分享者所見一致）就被破壞了。模式狀態需要能透過 URL 帶入（見第 2 節），且 URL 帶的值優先於 localStorage。

## 2. 機制設計

- 模式編碼進 URL（例如 `?mode=pro` / `?mode=plain`），分享連結時模式狀態一併帶走，滿足第 1 節第 3 條的可引用性要求。
- 頁面上有明確、隨時可見的手動切換入口（不是一次性引導流程跑完就消失）。
- 切換後的選擇寫入 `localStorage`，供**同一使用者、未帶 `?mode=` 參數時的下次造訪**使用；一旦 URL 帶有 `?mode=`，一律以 URL 為準，不寫回也不讀取 localStorage 覆蓋當次顯示。

## 3. 兩種模式的差異範圍（待定稿）

> 這節目前只定範圍，不定最終文案——第 5 節列的待辦尚未完成前，不能視為定稿。

- `pro`：沿用現有措辭（法律／議事用語，例如「三讀」「付委」「對照表」等專有名詞不額外解釋）。
- `plain`：同樣的節點、同樣的資訊，改用白話說明專有名詞在做什麼（例如「三讀」旁加註「最後一輪表決，通過就正式成為法律」），但**不省略、不簡化任何資訊本身**。
- 兩模式的差異只發生在「怎麼講」，不發生在「有沒有講」。哪些具體字詞、UI 文案要改寫，由第 5 節的懂法律背景審閱者會同事件線編輯決定，不是工程實作可以片面決定的事。

## 4. 預設模式：已拍板

> **2026-08-29 拍板：預設 `plain`（白話模式）。**

決策原因：專案核心目標是「降低公民參與門檻」。對熟悉議事術語的讀者（記者、幕僚、研究者）而言，切換 UI 或網址帶 `?mode=pro` 的操作門檻極低；但對一般公民而言，第一眼若是滿篇專有名詞容易直接跳出。搭配 `localStorage` 記憶機制（見第 2 節），專業使用者手動切換一次後即可維持 `pro` 模式，不影響長期體驗。

## 5. 白話用詞審閱：流程已拍板，內容審閱中

> **2026-08-29 拍板權責分工**：工程實作團隊不代勞、不自行編造白話文案定案版本。

審閱機制：

1. 工程端先提供一份「專業術語 ↔ 白話加註」對照字典**草稿**（見 `data/plain_language_glossary.json`，涵蓋「付委」「排入院會」「一讀／二讀／三讀」「黨團協商」「公布」「撤回」「不予審議」等通用議事程序用語）。
2. 由坑主／事件線編輯找懂法律背景的人員（或專案內的法律顧問／編輯）對該字典逐條核對、審定，確保法律效果（如是否已定案、是否有約束力）表達精確。
3. 審定完成後，工程端直接套用該對照字典，**不再逐節點人工修改**——字典是唯一真相來源，個別頁面不能有客製化文案跟字典不一致。

**目前狀態**：字典草稿已由工程端提供並接進網站（見下方待辦），前端在 `plain` 模式下會顯示這份草稿的加註，但每條加註旁都標了「草稿待審」，不冒充已經審過的定案文字——這是誠實呈現「機制已經在跑，但內容還沒經過第 2 步審閱」的過渡狀態，不是省略這一步。
