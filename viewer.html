這個版本跟靜態 mockup 的差別

  • 資料是即時打 API 抓的，不是手 key 進 HTML。立法列來自 LYAPI 真實議案流程；行政列來自行政院公報開放資料（data.gov.tw dataset 5959）。
  • 行政院公報只有「今天」的資料，非今日一律誠實標成缺口，不假裝查過。這是 API 本身的限制，不是程式偷懶。
  • 搜尋次數改用維基百科瀏覽量頂替 Google Trends：Google Trends 沒有官方公開 API，非官方介面（裸 request、pytrends 函式庫）兩種方式實測都被 429 擋掉。維基百科瀏覽量量的是主題頁面長期關注度，不是當天新聞搜尋量，關聯度較弱，已在格子裡標注⚠。
  • 「點閱率」列先併進「搜尋次數」，沒有另外開一列：兩者本質都是「公眾關注度」的代理指標，在 Cofacts 被 HF gated dataset 鎖住、搜尋次數又只有 Wikipedia 弱訊號的階段，開兩列各放一個缺口只會讓人以為在講兩件不同的事。等 Cofacts token 到手，再決定併回這列還是重新拆開。
  • 媒體報導列目前固定是缺口：還沒有結構化來源可信任。格狀資料結構已經留好位置，接上真資料時不用改這個檔案。
  • 立法列示範用的是食品安全衛生管理法修法線，不是共筆裡舉例的軍購特別預算案——因為 LYAPI 清單端點的查詢篩選目前實測是壞的，還沒能直接用關鍵字/提案編號查到那個特定案子的議案編號，需要先手動去 ppg.ly.gov.tw 查一次起點編號。
  • 立法節點加了兩種連結導引：① 每個節點卡片點得進 LYAPI 議案頁面原始連結；② 卡片下方「◀上一步／下一步▶」可以跳到同一條線的鄰近節點——如果鄰近節點不在目前顯示的日期範圍內，按鈕會變灰並標出它實際的日期，不會假裝跳得過去。
